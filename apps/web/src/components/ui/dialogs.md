# `src/components/ui/` — dialogs

The dialog primitives among the [deviations from official components](README.md); the rules
there apply to them too. Popovers and notices are in [`overlays.md`](overlays.md).

| File                         | Why it exists                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `modal.tsx`                  | The official `ModalOverlay` covers the whole screen (`fixed inset-0`, `min-h-dvh`), but iOS Safari and Android Chrome shrink only the visual viewport for the on-screen keyboard, so on a phone a dialog with a field ended up behind the keyboard. This `ModalOverlay` places the official one over the visual viewport on phones: at its offset (`useVisualViewportTop`) with React Aria's `--visual-viewport-height`. The file re-exports the official `Dialog`, `DialogTrigger` and `Modal` unchanged, so product code takes the whole modal set from here. A dialog's content keeps the official `Dialog`'s scrolling (no `overflow-hidden`), so a field stays reachable when the keyboard leaves little room.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `confirm-dialog.tsx`         | Untitled UI ships the modal pieces (`application/modals`, `FeaturedIcon`, `Button`) but no confirm dialog. The one confirmation for a change that cannot be undone, composed from them: title, close button, error-tinted featured icon with the consequence, an inline refusal (one text, or one chosen by the thrown cause), Cancel and a solid-red confirm with its loading state and, when given, a progress label in place of its own; it cannot be dismissed while the change runs. Used by `features/agents/profile-panel/agent-archive-section.tsx`, `features/agents/person-profile-panel.tsx`, `features/apps/app-editor-danger.tsx`, `features/workspaces/workspace-members-panel.tsx` and the Records deletes (`features/records/note-detail.tsx`, `report-detail.tsx`, `template-report-detail.tsx` and `record-side-chat-header.tsx`). The confirm has the caret as the dialog opens, so Enter confirms, a delete's included (task #101, Frank 11-12).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `popconfirm.tsx`             | Untitled UI has no popconfirm (its modals and popovers are bare). The second check for an irreversible change to one item the user owns, anchored to the button that opened it so the path stays short and nothing else is interrupted: composed from React Aria `DialogTrigger`/`Popover`/`Dialog`, `dialog-actions.tsx` (its row buttons, the same 40px as every dialog's), on the popover surface and motion `connection-status-pill.tsx` and `base/select/popover.tsx` already use (`POPOVER_MOTION`, grows from the trigger). It holds the question, an optional one-line consequence, an inline refusal (one text, or one chosen by the thrown cause), Cancel and a solid-red confirm named for the action, with a loading state and, when given, a progress label; it cannot be dismissed while the change runs, Escape and an outside click close it and focus returns to the trigger, or, after a confirm that removed the trigger, to the caller's `fallbackFocus` target (a list or section container made focusable with `tabIndex={-1}`). `isDisabled` keeps the same trigger element and its own `onPress` but never opens the popover, so a button that is a plain action in one state and a confirmed one in another (Start/Stop) keeps keyboard focus. A change that affects others, a bulk change, or one that needs a decision first stays a `ConfirmDialog`. Used by `features/computers/computer-detail.tsx`, `computer-detail-workspace-inventory.tsx`, `features/records/weekly-report-settings.tsx`, `key-point-prompt-editor.tsx`, `team-key-point-section.tsx`, `features/agents/profile-panel/agent-profile-header.tsx`, `agent-profile-tab.tsx` and `features/conversations/thread-following-agents.tsx`. Its confirm has the caret as it opens, so Enter confirms (task #101). |
| `dialog-actions.tsx`         | Untitled UI ships modal pieces but no dialog button row. The one row, as on Raft: right-aligned, 8px apart, a borderless Cancel or Close first, then the action, every button `useDialogControlSize()` tall: `sm` (36px) on a precise pointer, `md` (40px) on touch — the same size a dialog's `Input`/`Select`/`TextArea`/`ComboBox` takes from the same hook (task #224). Composes the official `Button`. Used by `confirm-dialog.tsx` (and so every confirmation), `features/computers/runtime-sign-in-dialog.tsx` and `features/computers/kiro-enterprise-sign-in.tsx`; other dialogs still lay out their own row and move to this one when they are next changed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `unsaved-changes-dialog.tsx` | Untitled UI ships no discard prompt. The one prompt a form overlay raises when it is closed with unsaved edits, composed from the modal pieces and `dialog-actions.tsx`: Keep Editing, Discard Changes and, only when the caller passes `onSave` (saving is one obvious action), Save and Close; the caller supplies the `description`. Beside Save, Discard is outlined; alone, it is the row's one solid-red button. `useUnsavedChangesGuard({ overlayOpen, dirty, close, onDiscard?, onSave? })` in the same file hands the form `requestClose` (Escape, outside click, the close button and Cancel all go through it) and the prompt's props, and `useReportDirty` lets a form inside the overlay report its edits. Used by `features/conversations/channel-settings-panel.tsx`, `create-channel-dialog.tsx`, `message-forward-dialog.tsx`, `features/agents/agent-create-frame.tsx`, `agent-runtime-config-dialog.tsx`, `features/apps/app-editor.tsx`, `app-review-reject-dialog.tsx` and `features/records/create-weekly-template-dialog.tsx`. The row's filled button (Save and Close, else Discard) has the caret as it opens, so Enter presses it (task #101).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `dialog-form-keys.ts`        | Neither Untitled UI nor React Aria submits a form from a multi-line field. Enter in a dialog's single-line field submits through the browser's own implicit submission (the dialog is a `<form>` whose action is `type="submit"`); in a `TextArea`, where Enter starts a new line, `submitOnModEnter` on the `<form>`'s `onKeyDown` submits on ⌘/Ctrl+Enter, through the default button and not while it is disabled, leaving an input method's confirming Enter alone (task #101). Used by `features/apps/app-review-reject-dialog.tsx`, `features/conversations/stop-channel-agents-dialog.tsx` and `channel-settings-info.tsx`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
