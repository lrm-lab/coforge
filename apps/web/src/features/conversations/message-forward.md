# Forwarding a message (web)

The server half is [`message-forwards.md`](../../server/conversations/message-forwards.md). The wording and layout follow Raft's.

- Forward is offered on a person's or an Agent's own message only (`canForwardMessage`): not on a forward, an action card, a server notice or an unsent (outbox) message. It sits in the hover bar's "…" menu with Save (the bar keeps the frequent reply, reactions and copy, as Slack's does), and in the tap action sheet after Reply in Thread and Copy. Rows reach the dialog through `useOpenForward`; `ForwardHost` (inside `ConversationHostProvider`) holds the one dialog and mounts it per opening, so a request id (`crypto.randomUUID()`) is one per opening.
- `message-forward-dialog.tsx` owns the flow; `message-forward-panes.tsx` draws the target list and the preview with its note. The panes sit side by side from `lg` and as two steps below it (CSS keeps both mounted, so the search and the note survive a step back). The picks show as removable chips ("To") above the note, so they stay in view while the list is filtered or a step behind; send is a labelled "Forward" button, and ⌘/Ctrl+Enter in the note sends. Pure rules (`message-forward-model.ts`) are unit tested; the flow is `test/e2e-message-forward.e2e.ts`.
- Up to ten destinations. A person or an Agent without a DM gets it opened (`openDirectConversation`) first, and a channel or DM opened or joined for a send is remembered, so a retry names the destinations its request id was first sent with. A public channel the viewer has not joined is tagged "Not joined" on its row and the button reads "Join and forward" while one is picked; nothing joins silently. A partial or total failure keeps the dialog, marks the failed rows and offers Try Again; success closes it and toasts "Forwarded to …" with View in Chat.
- `ForwardedMessageCard` is the one card: the stream row (the card holds the message's attachments, and the row's footer draws none), the dialog's preview, and the same row wherever Saved, search or Activity render one. Those three list a note-less forward as "Forwarded: …" (`message_forward_preview`); the server's previews (sidebar, activity events, Web Push) read it from `forwardPreviewText` as "↪ " and the original's text, a mark rather than a word, as they have no viewer locale.
