# Drafts (web)

The Drafts page (`/drafts` under Chat, `drafts-view.tsx`) lists every message the viewer typed and did not send, in any conversation of the current Workspace. It follows Raft's: a row goes back to where the text was written, and the composer there restores it from `localStorage`, so navigation is all a row does. A row has no delete or menu; sending or emptying the composer removes the draft.

- The page is an Experiment, like `taskConversations`, but with no flag and on by default (`flag: null`, `defaultEnabled: true`): every Workspace has it until an owner or admin switches it off in Settings → Experiments (`docs/feature-flags.md`). `loadDraftsOn` (`drafts.functions.ts`, gate in `src/server/conversations/drafts-gate.server.ts`) answers any member; `use-drafts-on.ts` owns its query (`draftsOnQuery`, prefetched by the `_chat` loader so the sidebar row and `/drafts` do not pop in) and reads again on `workspace.features.changed.v1`. Off, the sidebar row is not rendered, `/drafts` renders nothing and then replaces itself with Chat's index, and `landingConversation` does not land on a remembered Drafts view. A failed read counts as off, never as unknown. Storing and stamping drafts goes on regardless.
- Drafts are device-local `localStorage` entries (`composer-draft.ts`), which owns the key format both ways: `composerDraftKey` (`coforge.composer-draft:<conversationId>[:thread:<rootId>]`), `taskDraftKey` (a Task's discussion, `…:task:<boardConversationId>:<number>`) and their inverse `placeOfDraftKey`, which gives `{ conversationId, target }` (`target`: conversation, thread or task). Nothing is stored on the server, and the page lists what this device holds.
- A draft's last edit is `<key>:at` (epoch ms), written by `writeComposerDraft` only when the stored text differs from the new text. The composer rewrites the text it just read on every mount, so opening a conversation never moves its draft up. A draft with no stamp (saved before it existed) sorts after the stamped ones, by key; a blank text or `clearComposerDraft` removes the stamp.
- One notification mechanism: `subscribeComposerDrafts` (`composer-draft.ts`) tells a listener, with the changed draft's storage key (`null` when any may have changed: another tab clearing storage, or the first subscription), when a listable draft's text or presence changed, never for a file's comment draft or a draft's pins. A same-document `localStorage` write fires no `storage` event, so the writers there notify; the window `storage` event covers other tabs and is attached only while someone subscribes. Add a draft writer only through `composer-draft.ts`, or the page will not hear of it.
- `composer-drafts-index.ts` is a pure read: `listComposerDrafts` (a full scan) and one cached snapshot for `useSyncExternalStore` (`deviceDrafts`). The cache is patched from `composer-draft.ts`'s changes (`observeComposerDrafts`, always on, so it is right with no subscriber): a keyed change re-reads that draft's text and stamp alone and gives a new sorted list; only `null` drops the cache for a full scan. A keystroke therefore never walks every `localStorage` key.
- Not listed: a draft's `:pins` and `:at` siblings, a file's comment draft (`attachment-comments:`), and a text blank after trimming. Their keys do not have a draft's shape.
- `drafts-model.ts` (pure) holds `resolveDrafts`, `countDrafts` and `draftRoute`. They take one `homes` map (conversation id to channel or DM) that `use-drafts.ts` builds the way the sidebar lists them: channels from `channelNamesQuery` (not archived), DMs from `directEntries` (`directory-layout.ts`, the sidebar's own: a DM with a gone Agent is dropped, the viewer's own is named as the sidebar names it). Another Workspace's draft, or one in a conversation the viewer cannot see, is hidden, never shown as unknown.
- A row opens the channel or DM; a thread draft with `threadRootId` set, a Task draft with `task` set (the Task popup). Task discussion drafts are written only while task conversations are on, so `resolveDrafts` and `countDrafts` take `{ taskDrafts }` (`useTaskConversationsOn`, `features/tasks`) and leave task rows out, and out of the count, while it is off. The Task's title is the shared `overviewTaskQuery` (`features/tasks/use-finished-tasks.ts`, also the Tasks page's), falling back to `Task #N`.
- The sidebar row (`drafts-directory-row.tsx`, under Saved) shows a count only above zero. `useDraftCount` returns a number computed from the homes map, so a keystroke renders that row only when the count moves, never the directory.
