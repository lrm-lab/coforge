## 设计者四项新增（原意）

1. **并行子诊断**：相似 context 节点较多时，并行分发多个 diagnosis agent——每个的上下文与主 diagnosis 一致（同一诊断情境），但各自分析不同的跨树 context 轨迹，最后汇总。
2. **自评置信度的假想路径**：跨树信息汇总后做 counterfactual imagination，提出假想路径，路径上标注 LLM 自己预测的置信度。
3. **预测-实际对比信号**：evaluation 阶段有三种未来轨迹来源——guided replay、guided continuation、真实交互产生的未来轨迹。把"预测的假想路径"与"实际未来轨迹"对比，作为某种用途的信号（设计者未定用途，需拷问出协议）。
4. **假想轨迹变质 + 可恢复的诊断上下文**：假想轨迹基于部分相似 context 推导；新同 context 轨迹采集到后旧假想过期变质。设计者想法：保存之前 diagnosis agent 的上下文；相似 context 新轨迹产生时，在其上下文基础上让其看新轨迹（旧轨迹需要也可重看），判断之前的 imagination 是否需要调整变更；**稳定的 imagination 才更值得 replay/continuation**。

## 中间人预评审（你可以采纳、反驳或超越，问题要落在协议上）

- **并行子诊断**：map-reduce 合理。约束：①"上下文一致"必须落实为版本化的共享诊断简报（diagnosis_run_id + snapshot watermark + anchor + 草稿 context，不可变工件），不传活会话；②每个子 agent 输出结构化判定（相似性结论、关键差异、可借鉴模式），主 agent 按协议归并，防多数派锚定；③并行不得扩径 Q43 的路径预算（仍 ≤3 条）；④逐子 agent ACL；⑤子 agent 一次性、不持久。
- **自评置信度**：与 Q7 已决"不接受无校准自评"冲突。解法：初始置信度只是**先验**，须经预测-实际记录校准后（按 cluster × model_version 分桶，Brier/可靠性曲线）才可作排序权重。
- **预测-实际对比**：用途至少五种——①校准想象；②具体化 Q6"经验证才持久化"（同簇真实轨迹与假想吻合 = 验证通道之一，配对 replay 是另一通道）；③惊讶信号（大预测误差 = 新失败模式/环境变化 → 自动生成 fork 候选）；④guidance 效用证据；⑤簇级预测能力表。两个坑：①路径对比不能精确匹配，须语义检查点（结果类别、关键中间状态、动作类型序列）+ 判定 provenance；②跨树对比中不匹配可能源于 context 差异而非想象错误 → 校准必须簇条件。三源证据权重：真实 > continuation（被 guidance 混杂）> replay（隔离但模拟）。
- **变质与可恢复诊断上下文**：①不要持久化活 agent——持久化**可恢复的诊断档案（dossier）**：anchor + 最终 context + 检索候选集 + 相似判定 + 簇连接 + 各假想及其证据基础 refs + 未决问题 + 续诊指针（哪个 revision、等什么新证据）。新 run 以档案为种子重建 agent。②变质机制不是纯时钟 TTL，而是**证据基础失效**：新同簇轨迹到达 / 簇成员变更 → 基础分布偏移 → 过期；有效置信度 = 校准置信度 × 新鲜度因子；过期走 supersede revision，不删。③增量再诊断事件触发（新同簇轨迹 commit、新相似边、预测误差超阈），预算小于首诊。④判断漂移审计：新模型版本翻转旧判定必须记版本差，判定变更是新 revision。⑤"稳定才值得 replay"落成 replay 候选评分：revision 变动率低 + 校准置信度过阈 + 所在簇真实证据量足够。⑥防自证回声：续诊判定尽量换模型版本，且不改变 evaluator 下游独占审批。
- **中间人延伸（请评估采纳与否）**：集成想象（多模型/多温度独立想象，分歧=不确定标记）；惊讶驱动候选生成；想象分支双验证通道（同簇真实吻合 或 配对 replay 成功）；簇级校准表指导"哪类情境用哪个模型做想象"。
