# Fork Node 体系设计共识（OpenViking × coforge）

本文件是 2026-09-23/24 起持续多轮设计拷问（griller：kiro/gpt-5.6-sol、ZCode/GLM-5.3 等；设计者：zhoujie22）的 living consensus。早期问题原文与逐轮答复见 round questions/answers 文件；术语见 [CONTEXT.md](./CONTEXT.md)；不可逆决策见 [docs/adr/](./docs/adr/)（0001–0043）。

> **现行模型注记（2026-10-12）：** 对 Fork/AIG 的新写模型，以 [ADR-0043](./docs/adr/0043-aig-native-fork-overlay-and-guided-remediation.md) 与 `CONTEXT.md` 的 Q166–Q189 为准。本文件中依赖 `InfluenceClaim`、`cut` grounding、独立 L3 `ForkRevision` 或由 Diagnosis 生成 Fork 的叙述，仅保留为 legacy 只读审计/迁移语境，不能与 ADR-0043 一起被解释为新写入要求。其余未被 ADR-0043 明确取代的 AO ledger、ACL、provenance、检索、效用与审计约束继续有效。完整关系见 [需求一致性审计](./docs/requirement-consistency-audit-20261012.md)。

## 一、端到端架构（最终形态）

### 写入侧（session commit 时）
1. commit 照旧归档 messages.jsonl 原文、生成 Working Memory `.overview.md`（ov_wm_v2 语义不变，**不承担节点抽取**）。
2. 新增 **AO 台账**：本批每个 action-observation pair 一条记录；observation 走确定性 synopsis（复用 `tool_result_synopsis.py` 思路），大结果外置引用；**必带 `skill_invocations[]`**（skill_uri + revision_hash + invocation_id?，未用显式 `[]`，禁止事后推断）。
3. `ao_id` 在写入 append-only live ledger 时即发号，**deployment 内全局唯一、永久不变**；commit 只追加归属解析（archive_id + commit watermark），绝不重编号。
4. 行为由 `memory.skill_trajectory_mode = legacy | causal` 决定（全局默认 → workspace 覆盖 → session 创建时固化）；legacy = 原始 OpenViking；causal 统一 gate 台账、fork 构造与消费、proposal/replay/guidance/统计。**新建群创建时，其群 session 强制固化为 causal，不依赖当时的全局或 workspace 默认，以保证首条群事件起的轨迹归档。**

### 诊断侧（按需）
5. 诊断 agent 经 `list_ao_ledger` 分页读台账（可跨 commit；`include_live=true` 可看活会话；snapshot watermark 冻结读视图），必要时经 `get_ao_evidence` 下钻原文（来源 session ACL 二次校验，全程审计）。
6. 定位问题点/可改进点 → 在该处构造 **fork node**：七段状态快照 + causal context（**双字段**：`contemporaneous_basis_ao_ids[]` 严格早于锚点 = 当时依据；`hindsight_attribution_ao_ids[]` 可含锚点后 = 事后归因，二者在 schema/展示/prompt 层硬隔离）+ `used_skills[]`（仅从 selected_evidence 覆盖的台账条目机械回填）+ 未来分支。
7. 锚点为判别式三种：`ao`（历史动作）、`session_state`（当前状态快照锚点，冻结 watermark + live 上界，revision 用 supersedes 递进）、`interaction_edge`（跨 agent 协同决策点）。稳定身份 = {workspace_id, anchor_kind, canonical_anchor_key}；同锚点重复诊断**复用** fork_node_id、追加不可变 revision/branch，不覆写。
8. 写入走受控路径：agent 仅持 `causal-experience:propose`，提交 ForkNodeUpsert 到 durable command/outbox；服务端验证（AO 存在、ACL、schema、synthetic 标记、配额）后原子落 `viking://~/causal-experiences/` 权威记录并异步投影；幂等键 = diagnosis_run_id + anchor + content_hash。agent 不可直写索引/统计/已 .done archive/executable skill。
9. 跨 commit 的证据引用带九字段 provenance（ao_id、session、archive/live、commit 水位、sequence、读快照、evidence_role、content hash、committed/live）。

### 分支与对照实验侧
10. 未来分支三类：**真实分支**（后续交互回填）、**想象分支**（完整 AO 序列含合成 observation，逐条标 synthetic；诊断期生成，验证后才持久化；检索排序恒低于真实）、**guidance**（**分支的字段**，不独立检索；引用跨 commit AO 带完整 provenance）。
11. replay 由 coforge daemon 判定（七步：来源完整有权限、初始状态可重建、工具版本可执行、逐工具副作用隔离、临时最小权限凭据、非确定性可控、预算合规；任一不过 → 持久 ineligible job + 走 guidance append 路径）。可行时由一次性隔离 worker（copy-on-write 快照、默认禁网、无生产凭据）执行：≤3 个 skill revision ×（1 guidance 分支 + 1 配对无 guidance 基线）≤ 6 条；每分支 16k token / 25 工具调用 / 10 分钟；全局并发 2。
12. 不可 replay 时，structured guidance event 在锚点快照后 **append 到 session 尾部**（专用事件、不伪装对话；WM/key-step/skill 三个 extractor 默认过滤；显式 adoption 才关联 outcome 计效用；带 TTL，过期不注入）。

### 晋升侧
13. 归因报告（带证据 node ID）→ **proposal**（独立带 ACL 命名空间；draft 可检索但带"未验证"标签，仅可用于归因与 guidance，不可由 Diagnosis 直接写 skill）→ 服务端仅做 schema、ACL、provenance、content hash 与幂等完整性校验 → 自动进入 **Agent Evolution**。独立 evaluator/promotion approval gate 已由 Q11-C 移除；Evolution 仍是发布/更新 executable skill（稳定 URI）的唯一通道。Q13-C 规定同一原子 transition 产生不可变的 `published_active_skill_revision`，立即具备适用 scope 内的在线检索与执行资格；active 不表示正效用、必然高排名、强制采用或绕过常规 ACL、安全、兼容性与撤销硬门。fork node 仍是证据层，无 case 仍不出 skill。

### 多 agent 侧（群聊）
14. 群聊消息 = **共享 interaction event**（服务端发不可变 message_id + channel sequence + 内容 hash）；各 agent 的 AO 台账分别记 `channel.send`（action）与 `channel.receive`（observation）；**segment** = 某 participant 被 interaction event 截断的本地 AO 区间，去重键 {channel, event, participant, direction}。
15. **interaction DAG** 由通道服务实时 append-only 物化（节点：segment + interaction event；边：local_continuation / emit / deliver），权威存群聊 interaction store；causal-experiences 只存 fork 引用。OpenViking 为每个群参与 agent 的可采集历史轨迹保存完整、可审计的归档副本，并以稳定引用关联共享 event/DAG，但绝不成为第二权威。**群创建时立即 provision 一名具有独立 identity 与 session 的稳定 Memory Agent；它从首条群事件起作为成员接收消息，而非按 task 或 thread 临时创建。**其中「每个新建群各自 provision 一名独立 identity」自 2026-10-13 起由 `default-memory-agent/Q217–Q235` 取代；不按 task 或 thread 临时创建仍然有效。诊断 agent 经 `traverse_interaction_dag` 沿边看全局历史，权限 = 群聊 capability ∩ 来源 session ACL，无权内容 redacted，成员身份不隐式提权。

### 统计与检索侧
16. 共现与效用由**异步 aggregator** 维护全局物化统计（以 fork_node_id 聚合，按 revision 区分结论）；正向效用仅认"实际采用 + 可观测成功/无纠错"或"配对 replay 相对基线的可观测改善"；曝光不计分；proposal/Guidance 生成方的自报成功不构成效用证据。Q11-C 移除的是独立 promotion Evaluator，不移除客观 outcome 与对照证据。
17. 检索入口仅两类：**fork node**（规范化七段 context embedding）与 **branch**（父状态摘要 + 动作序列 + 结果/失败模式 + guidance 摘要）；branch 命中回溯 parent node；投影轻量（不含七段全文/原文/敏感 guidance），读证据二次 ACL。

### 评估编排与跨树簇（Round 7）
18. **评估编排**：fork node 由服务端**权威提交成功**后触发（不是 agent 提议时）；第一步 daemon 七步 replay 判定，ineligible 显式走 guidance append；replay 结果、客观 outcome 与归因报告保留为 proposal 的审计和效用证据，但不再经过独立 evaluator approval；proposal 完整性校验通过后自动进入 Agent Evolution；同 revision 幂等（fork_node_id + revision_id + policy_version）。
19. **候选提议与相似性审计**：agent 每 run 提议 ≤5 候选、每候选 1 份浅层草稿（不生成完整七段）；升级门槛 = 可审计选点理由（跨树相似案例是增强证据、非前置条件，冷启动不需要检索）；未成 fork 候选写入受 ACL 保护、不可检索的 diagnosis-run provenance。相似判定四维（任务/决策类型、锚点时状态、失败模式/因果、行动与 skill 角色），verdict 四值（consistent/analogous/insufficient/dissimilar），全程 provenance；dissimilar 作负样本仅用于离线检索改进。
20. **跨树簇**：相似性边 verified_similarity_edge 为一等对象（连接两个 fork revision、带判定 provenance、endpoint 去重、幂等键 = run + pair + judgment_hash）；簇为**中心式、可重叠**（成员须与 center 有已验证正向边；A~B、B~C 不传递；merge/split 创建 successor，旧簇只读封存；cluster_id 首条正向边时铸造、永不重算）；维护完全复用 propose→服务端验证→原子提交→outbox。
21. **簇条件效用与晋升**：utility(cluster_id, branch_pattern / skill_revision, evidence_status) 为主视图，全局效用仅是带样本量与异质性的聚合视图；共现降为辅助信号；proposal 生成条件 = 已验证簇内反复出现、带独立真实正向效用的分支模式；这些生成门槛继续有效，但独立 evaluator 尾门由 Q11-C 移除，完整性校验后的 proposal 自动进入唯一发布通道 Agent Evolution。
22. **路径参照与并行子诊断**：draft context 可直查 branch；有界 expand_branches / walk_path（≤12 轻量候选、≤3 条参照 path、每条 ≤2 hops / ≤12 实体、逐跳 ACL、redacted 断点）；参照排序：真实且正向效用 > 真实无记录 > 已验证想象（未验证想象不进跨树检索）；replay 候选 skill 只来自语义验证通过、真实且有正向效力的 branch 所用 revision。并行子诊断 = 冻结不可变 diagnosis_brief + ≤3 个一次性 worker（权限 = 主诊断 ∩ 来源 ACL）+ 主 agent 按证据归并（非多数投票）；并行只降延迟，总预算不扩张。（Round 10 Q115-A 补注：评测迭代内由统一 5 并发席取代；独立诊断 run 与 dossier 增量预算维持本条。）

### 假设层：置信度、预测-实际对比、变质与再诊断（Round 8）
23. **置信度与校准**：想象分支的自评置信度必须锚定 forecast_contract（预测"同簇可比情境中该分支是否与实际轨迹在语义检查点相符"），原始值只是先验；按 {cluster × model_version × policy_version} 分桶，攒满 **30 条真实交互可比结果**后才产生可用于排序的校准置信度（continuation/replay 不得凑数）；高价值候选可跑有界双样本集成（优先异模型），分歧记 disagreement 降权。
24. **预测-实际对比**：判定按 forecast_contract 的语义检查点（结果类别、中间状态谓词、动作类型序列、失败模式、比较窗口），输出 match/partial_match/divergence/insufficient_evidence；context 不同先判 incomparable_context_shift；三源质量系数 真实 1.00 / guided continuation 0.60 / guided replay 0.35；信号落点五类——簇条件校准表、想象分支验证通道一（同簇真实吻合）、通道二（配对 replay 改善）、surprise event（高质量可比 divergence → 浅层 fork 候选草稿，仍走 Q26）、簇级模型预测能力表（imaginer 路由）。
25. **变质模型**：驱动是证据基础失效（新同簇真实轨迹、簇成员/边变更、预测误差越阈、证据 redaction/ACL 变化），不是时钟 TTL；状态 fresh 1.0 / needs_revalidation 0.5 / invalidated 0.0，有效置信度 = 校准置信度 × 新鲜度；一切调整走 supersede revision，旧分支保留为历史证据。
26. **可恢复再诊断**：持久化 diagnosis dossier（anchor、最终 context、检索与判定、簇连接、各想象分支及证据基础、forecast contracts、未决问题、等待条件、预算与版本），不持久化活 agent；四类事件触发增量 run（重新过 ACL），预算 ≤4 候选 / 1 path / ≤首诊 50%；优先异模型续诊（同版本须标 same-model-continuation）；判定翻转记录模型/policy 差异并形成新 revision。
27. **稳定性与 replay 投资**：imagination 获得 replay_investment_eligible 须同时过六门槛（校准且有效置信度 ≥0.70；fresh；簇内 ≥3 条真实证据来自 ≥2 session；近 3 次证据事件未翻转结论；双样本通过或带降权；本次过 ACL/七步/路径限制）；稳定想象只影响既有合规候选的投资排序，不能引入新 skill、不能绕过真实效用门槛；验证双通道任一成立 → validated，均无 → hypothesis。Q11-C 仅移除独立 evaluator approval；合规 proposal 在服务端完整性校验后自动进入 Agent Evolution。

### Memory/Diagnosis 共享检索（Round 9，已定案）
28. **共享机制、分离策略**：Memory Agent 与 causal Diagnosis Agent 共用 typed retrieval facade、ACL/fence、预算记账、审计与 provenance；fork/branch、segment/atom、generic memory 保持独立 adapter。两类 agent 使用不同 retrieval profile，不共享统一 TopK、展开策略或停止条件。
29. **任务状态与双向交接**：Memory Agent 的可变状态称为 MemoryTaskState，与七段 Working Memory、长期记忆事实和诊断权威证据分离；每个 task_id 一条 lineage、每个 run_id 一份可变状态。评测多次运行时形成 `Memory Agent → Diagnosis Agent → Memory Agent` 循环。两类 agent 可通过活 session 保持语义连续性，但跨 run 的权威交接仅认不可变 brief/outcome、带 provenance 的 refs、Memory Hint 与摘要；不把活 session 当恢复或幂等边界，交接物本身不授予额外读取权限。
30. **群聊角色**：Memory Agent 是群聊成员；Diagnosis Agent 是后台 per-run agent。服务群聊任务不意味着二者继承相同可见范围。
31. **双层评测/诊断**：step-reward scorer 是独立前置评测器，只提供候选定位信号；只有 causal diagnosis 可以提出 fork node、分支与跨树关系。step reward 不构成因果结论。
32. **全局可检索 ForkCandidate**：causal diagnosis 在 replay/continuation 多轮评测中生成 ForkCandidate，并立即投影到普通全局 Memory 检索，以显式 provisional 状态与 validated ForkRevision 区分；后续 Memory Agent 将其转成 Memory Hint。候选进入 exposure/citation/adoption/outcome 四层评价，引用按 in-task/cross-task 双维强度、指数时间衰减和 exploration propensity 去偏处理，不能凭引用自动晋升。
33. **权限与预算分离**：Memory 与 Diagnosis 分别持有独立 capability、pinned SearchPlan 与子预算，受同一 task/evaluation 父级总上限约束；每次跨 ref/边重新检查来源 ACL，不传递 credential 或余额。
34. **Memory Hint**：fork node 或 ForkCandidate 作为记忆消费时返回带类型、来源、适用性和置信状态的 Memory Hint，不伪装为 executable skill；只有 Evolution 发布的稳定 skill URI 可进入执行通道。
35. **同任务与跨任务迁移**：相同 task_id 是强排序特征而非自动采用证明；跨任务按任务/决策类型、锚点状态、失败机制、行动与 skill 角色四维重排。在线 Memory Agent 不创建 verified similarity edge。
36. **双 lane 与全局 bridge 分型**：Memory 检索分为 Interaction lane 与 Causal-memory lane，独立计候选、跳数和停止条件，在 MemoryTaskState 中归并；模型可在任意两类节点间提出 `HypothesisBridge`，该边创建后全局长期可遍历，但仍只表达待探索关联。只有由 provenance 或服务端验证产生的 `EvidenceBridge` 可支撑 fork 归因；HypothesisBridge 晋升必须走 causal diagnosis propose→validate。
37. **四层价值信号与双维引用强度**：全局 ForkCandidate 分开记录 exposure（不计 utility）、citation、adoption 和 outcome。全部 citation events 在发生时等权贡献初始 reference value，原始事件永久保留，物化分数随年龄衰减；引用方与记忆来源属于同一 task lineage 时进入 `in_task_reference_strength`，不同时进入 `cross_task_reference_strength`。两维与 outcome_utility 分栏。
38. **统一子 agent 上限**：InteractionPathWorker 按有界 interaction path/subgraph 分片，返回结构化 assessed refs、mechanism、applicability、contradictions 与 evidence refs，由主 agent 归并。每次 Memory→Diagnosis→Memory 评测迭代中，InteractionPathWorker、sub-diagnosis worker 与其他 explorer 统一最多并发 5 个，共享固定总预算。
39. **假设桥路径硬边界**：每条探索 path 最多跨 2 条 HypothesisBridge、最多 12 个实体，禁止重复节点/边；每个端点必须重新与原始 query/MemoryTaskState 做直接适用性检查，间接路径不得自动产生 verified similarity、citation 或 EvidenceBridge；5 个 workers 共享总路径预算。
40. **引用时间衰减**：citation 原始事件永久保留；in-task 与 cross-task 物化强度采用 policy-versioned 指数衰减 `2^(-age/half_life)`，各自配置 half-life；策略变化重算投影，不覆写事件。
41. **双召回通道**：EvidenceBridge/ForkRevision 进入 verified channel，HypothesisBridge/ForkCandidate 进入 provisional channel，各自独立配额和内部排序后再带状态标签混合输出；hypothesis citation 只影响 provisional 通道内部排名。
42. **全局假设图治理**：HypothesisBridge 按 canonical endpoint pair + relation type 聚合去重、保留每次 model judgment；服务端验证 endpoint/type/ACL，施加 per-run 写入配额与 per-node active-edge cap；超限时最低“直接相关性 × 时间衰减 × 引用强度”边转 inactive，仅退出遍历索引，不删除审计记录。
43. **假设桥晋升**：citation/traversal 只提高再诊断或验证优先级，不能自动晋升。HypothesisBridge→EvidenceBridge 必须由 causal diagnosis 提交直接 evidence refs、关系语义与反例检查，走 propose→server validate；仅 citation provenance 明确包含 bridge_id 时给该桥计引用。
44. **Fork 三阶段状态**：`ForkDraft` 仅存在于 diagnosis run；服务端通过 schema、anchor/ref、ACL、provenance 与幂等校验后提交全局可检索 `ForkRevision(status=provisional)`，其消费角色称 ForkCandidate；获得因果验证或反证后追加 superseding `ForkRevision(status=validated|invalidated)`。权威提交表示记录及来源被接受，不等于因果结论已验证；Round 7 的“权威提交触发评估”由 provisional revision 触发。
45. **Citation 默认衰减**：in-task half-life = 7 days，cross-task half-life = 90 days；版本化 policy 可调整并重算投影。
46. **双通道默认配额**：每次最多 12 个轻量候选，verified 8、provisional 4；通道不足可回填，输出保留状态、来源通道与原始通道内 rank。
47. **假设图默认容量**：每个 evaluation iteration 最多新增/更新 12 个 endpoint-pair hypothesis judgments；每节点最多 32 条 active outgoing HypothesisBridge；workspace 只能收紧全局安全上限。
48. **ForkRevision 因果验证门槛**：provisional 仅在 anchor/ref/ACL/provenance 仍有效、至少一条原始 observed branch、至少一个独立对照支持、完成四维适用性与反例检查且无高严重度未决矛盾时追加 validated revision；高质量可比较证据反驳核心机制则追加 invalidated revision；证据不足保持 provisional。Citation 不改变验证状态，各 branch 保留自己的验证状态。
49. **评测循环停止与恢复**：ForkCandidate 进入 validated/invalidated、replay/continuation 不合资格、父级预算/时间/分支上限耗尽，或连续 2 个 iteration 无新增 evidence refs 且关键判断不变时，停止当前 Memory→Diagnosis→Memory 主动实验；未终态者保持 provisional，dossier 保存 waiting conditions，由未来真实证据事件重启一次性 run。
50. **Inactive bridge 再激活**：新 model judgment、明确包含 bridge_id 的 citation、adoption/outcome 或 direct-relevance 重验触发治理分重算；重新进入节点 top-32 且 ACL 有效时追加 reactivated 状态事件并恢复 active。Exposure/traversal 不触发，EvidenceBridge 晋升仍走 propose→validate。
51. **角色化通道内排序**：先执行 ACL、状态、freshness、直接适用性硬门槛，再使用 policy-versioned、role-specific reranker。Verified 侧以语义相关、evidence quality、outcome utility、新鲜度为主、citation 为辅；provisional 侧以语义相关、直接适用性、judgment 一致性和衰减后的 in-task/cross-task reference strength 为主。保存 feature breakdown、模型/policy 版本与确定性 tie-break；Memory/Diagnosis 可有不同权重，但不改变默认 8/4 配额。
52. **独立对照契约**：配对 replay/continuation 冻结 ControlContract（同一 anchor/state snapshot、任务输入、agent/model/prompt policy、工具与依赖版本、权限、预算和独立 evaluator），treatment 与 baseline 的唯一计划差异是目标 Memory Hint/guidance；非确定性用配对 seed 或有界重复并报告方差。关键冻结项不满足时只作 supporting evidence，不单独满足 ForkRevision 验证门槛。
53. **Memory Hint 定向投递**：Memory Agent 通过 `memory@target_agent` 发送 Hint；被 @ 的任务 agent 对每个已处理 Hint 输出结构化 MemoryDisposition(adopt|reject|defer)，独占采纳决定。超时无回执只算 exposure；后续 followthrough/outcome 独立记录并计值。回执通道以 `memory-disposition-receipt/Q190–Q216` 为准。
54. **Provisional 3+1 探索**：默认 4 个 provisional 槽中 3 个按 reranker exploitation，1 个从通过硬门槛的低曝光/高不确定候选中 seeded exploration；无合格探索候选时回填 exploitation。记录 eligible set、selection propensity、seed 和 policy version，供曝光偏差校正。
55. **Cross-task 身份**：task_id 不同即进入 cross-task reference strength，不引入 task_family 或 derivation 独立性门槛。仅权威 task/evaluation orchestrator 可铸造不可变 task_id；replay、continuation、baseline/treatment 和恢复 run 继承原 task_id；新顶层任务实例铸造新 ID，即使文本相同也不按内容 hash 合并。
56. **目标 Agent 处置与履行**：Memory Agent 经 `memory@target_agent` 定向投递；目标 agent 对每个已处理 Hint 输出结构化 `MemoryDisposition(decision=adopt|reject|defer)`，拥有采纳决定权。Reject/defer 仍形成 citation，超时无回执仅算 exposure；后续由独立机制记录 followthrough=observed|partial|not_observed|contradicted 和 outcome，只有 adoption + followthrough + 正向 outcome 形成正向 outcome utility。回执的工具、字段、事件与失败分类以 `memory-disposition-receipt/Q190–Q216` 为准。
57. **探索去偏**：原始 citation 继续等权记录并时间衰减；基于 seeded exploration 保存的 eligible set/selection propensity 生成 policy-versioned debiased_reference_signal，仅用于离线评价与下一版 reranker，不即时修改当前 policy。Exploration Hint 显式带 selection_mode=exploration，其 disposition/adoption/outcome 正常记录。
58. **评测状态机所有权**：EvaluationOrchestrator 独占 `创建 MemoryTaskState/SearchPlan → Memory 检索与 memory@ 投递 → task run → step-reward/结果评价 → 冻结 DiagnosisBrief → causal diagnosis → 服务端提交 ForkRevision/DiagnosisOutcome → 下一 run MemoryTaskState → 停止或 replay/continuation` 的状态迁移。Memory/Diagnosis 只能提交 trigger/schedule proposal，不能自行创建 run、扩预算或越过状态。
59. **ACL-safe 在线聚合**：citation/disposition/followthrough/outcome/judgment 事件冻结来源 task/channel、目标 Hint/ref 与主体安全标签；在线检索、引用强度、outcome 和治理分只使用当前 principal 可见事件，不返回隐藏事件数、task ID 或可反推小样本差值。服务端内部全量聚合仅用于受控离线评价，并经阈值化/去标识产物进入下一版 policy，不把私有精确总数注入在线排名。
60. **活会话 + 幂等信封**：Memory/Diagnosis 可用活 session 维持语义连续性；服务端同时持久化不可变、内容寻址 DiagnosisBrief/DiagnosisOutcome handoff envelope，以 `evaluation_iteration_id + handoff_kind + input_manifest_hash` 幂等并采用 at-least-once 投递与 ack/checkpoint。重复投递返回原结果，不重复写 fork/citation 或扣预算；输入变化创建新 iteration。Envelope 不带 bearer credential，接收方以自身 capability 逐 ref 重验。
61. **Influence View 层与 Fork grounding**：在权威 AO/Interaction DAG 与长期 Fork 层之间建立通用 L2 Influence View。IG 与 AIG 共用该层的 InfluenceBlock/InfluenceClaim schema，作为兄弟构建模式而非前后流水线；默认 `construction_mode=adaptive_agentic_aig`，直接从同一冻结 L0/L1 证据快照和空图构建，不读取 IG。IG 是可显式选择的非默认 `construction_mode=fixed_partition_single_pass_ig`，用于显式低成本构建、评测基线和 AIG 消融；AIG 失败时不自动改跑 IG。`fallback` 是确定性最小视图，与论文 IG 分开。每条 causal/evaluation 轨迹 commit 后异步生成 `purpose=post_run_index` frozen revision；失败诊断以其为基础派生 `purpose=failure_diagnosis` DIV revision。Draft 和完整视图不进普通检索；仅 frozen Block/Claim 轻量 projection 进入 provisional mixed retrieval。每个 ForkRevision 必须以 `influence_grounding` 定位到冻结 view 的 `block | edge | cut`，ForkNode ID 仍由 canonical anchor 派生。
62. **Segment→InfluenceBlock 原子边界**：Segment 是单 participant 由 interaction event 截断的连续 AO 事实区间；每个 InfluenceBlock 必须属于单一 participant，并引用同一 Segment 内连续 AO 区间。一个 Segment 可拆成多个 action-level Block；跨 agent、跨 Segment或非相邻影响只能通过 InfluenceClaim/subgraph 表达，不能压进一个 Block。
63. **Memory Hint 是终端消费事件**：Hint 属于 task/run，可综合多个 Fork/Branch/Guidance/Skill 来源并经 `memory@target_agent` 投递；不作为 ForkNode 可变字段、不进入普通检索索引、不作为 explore 中转节点。Memory/Diagnosis 仅可沿其 provenance 反向追溯来源，用 hint_id 关联 exposure/disposition/followthrough/outcome。
64. **Guidance 双重 grounding**：Guidance 继续作为 Branch 字段；semantic basis 引用冻结 Influence View 的 block/claim/cut，解释影响机制；factual basis 直接引用 AO/Segment/raw evidence 与既有 contemporaneous/hindsight provenance，提供权威复核。Influence View 引用不得替换事实引用，事实列表也不得替代语义机制。
65. **Influence View 冻结与 fallback**：Post-run indexing 或 diagnosis build 内，Builder/Refiner 只修改 mutable InfluenceViewDraft；最多 3 轮 critic/refiner 后冻结不可变 InfluenceViewRevision，Reader 只读。Critic 先运行确定性 `Phi(G)`：论文评测使用 `validator_profile=paper_exact`（连通、无环、唯一 task 根、唯一 conclusion 汇，connectivity 解释随 benchmark policy 版本固定）；生产使用 `validator_profile=production_grounded`（L2 虚拟 task root 与 observed-outcome sink、无环、弱连通、root→sink 可达，并检查 refs/watermark/hash/ACL/时序/omitted-range skip），不得将任一 profile 下的结构通过解释为语义或因果已验证。自适应构建失败、超时或仍有高严重度 violation 时，服务端从 selected AO/Segment 生成 deterministic minimal fallback view，标记 construction_mode=fallback；可参与 provisional projection或供 Fork grounding，但不能单独满足 validated 门槛，后续变化新建 view revision。
66. **层级生成原则**：L0 原始证据/AO 与 L1 Segment/Interaction DAG 在 runtime/channel 事件时确定性实时生成；L2 Influence View 由 LLM 自适应构建，结构检查/fallback 由确定性服务执行；L3 Fork/Branch/Bridge 由 LLM propose、服务端验证提交；L4 Hint/Disposition 由 Memory/目标 agent 生成解释性产物，投递、事件记账与 skill 完整性校验由服务端确定性执行。检索模型不因此获得事实写入或 skill 发布权。Builder 只能提交 snapshot-scoped opaque row handles 和语义字段；唯一 `AoGroundingService` 以调用者 principal 解析 canonical AO、校验 ACL/watermark/hash/participant/session/segment/连续性/overlap，派生 SourceRef/EvidenceRef 后原子 freeze/register，模型不得铸造或直接持久化 `ao_id`。
67. **Influence View mixed retrieval**：Memory 的 typed multi-corpus 检索同时覆盖 Fork/Branch、frozen InfluenceBlock/InfluenceClaim 轻量 projection 与当前 Segment/Atom；服务端执行 BM25/vector/ACL/配额/初排，主 Memory LLM 决定 expand、可派只读 path workers并完成跨 corpus 最终 rerank与Hint生成。Influence View 提供密集 action/influence 召回，Fork 保留稳定 anchor、branch、guidance、utility 与验证状态，二者不互相替代。Memory 只能通过 ACL-scoped、summary-first 的受限 `T_log` adapter 下钻：默认允许 overview/question/单步或有界区间/search/frozen graph；`read_full_log` 仅在显式 evidence escalation、scope 与预算均允许时开放；`list_agents` 不返回其他 agent 的完整 system prompt；永无 draft、critic 私有状态或 `T_build` 权限。Builder/Critic/Refiner/Reader 不直接调用有状态群 Memory Agent，而以自身 role/principal/scope/watermark/SearchPlan/budget 调用共享 retrieval facade；返回信封硬分 `current_evidence_refs[]` 与 `analogical_prior_cards[]`，只有前者可支持当前 Claim。
68. **Reader/Diagnosis 阶段式合并与角色会话隔离**：每个 AIG construction run 中，Builder、Critic、Refiner 各自拥有互不共享的 run-scoped session；Critic 与 Refiner 可在同一 run 的最多三轮修订中各自复用本角色 session，但不得跨 run 复用。Reader 与 Causal Diagnosis 共用一个活 CausalDiagnosisAgent session，但服务端强制 phase gate。READ_VERIFY 只能读 frozen Influence View/selected evidence、调度只读 workers 并输出内容寻址 ReaderReport，不能 propose Fork；冻结报告后进入 SYNTHESIZE_PROPOSE，只能基于报告 propose ForkDraft/bridge，不能修改 view/report。稳定群 Memory Agent 始终保有自己的长期 session，不与上述任一角色共享会话；角色间只通过冻结 draft hash、ViolationSet、ReaderReport 等不可变交接物通信。Q11-C 删除后续独立 promotion Evaluator，但不得将 Reader evidence verdict 偷换为 skill promotion approval。
69. **InfluenceClaim 证据验证与 raw AO 下钻**：Claim 由 Builder 创建时永远是 hypothesis；Reader 分别核验 source 产生 carried_artifact、target 实际消费、downstream_effect 出现及 alternative source/反例。全成立且无更强反例为 supported；直接证据否定核心项为 contradicted；其余 insufficient。Critic verdict 与 Reader evidence verdict 分栏；supported 也不自动生成全局 EvidenceBridge。Raw AO 采用 `required_capability + on_demand_selected` 而非自动全文注入：Reader/Critic 必须具备 selected raw AO 读取能力，Builder 按需，Refiner 仅 violation-local，Memory/Diagnosis summary-first 后显式升级；任何 ref 因 ACL/撤回/水位无法读取时只能记 insufficient/redacted，不能猜测通过。
70. **Influence projection 可见性**：Memory 全局 search 只返回 frozen InfluenceBlockProjection/InfluenceClaimProjection；同 task/evaluation 可按已知 ref 读完整 frozen selected blocks/claims，跨任务命中后须逐 ref ACL 与 evidence escalation；draft、critic 私有状态和未冻结内容永远不可见。
71. **Summary-first evidence escalation**：Memory/Reader 按 `projection → Block/Claim summary → evidence synopsis → selected raw evidence` 渐进下钻，每级可停止并独立计预算、ACL 与审计；命中上层对象不自动注入全部底层内容，redacted ref 构成路径断点。

### post-run 索引经济性、混合检索与自主监听（Round 10，已定案；griller：ZCode/GLM-5.3 接替 kiro）

72. **post_run 视图有界目的性覆盖**：以"task 目标 + observed outcome"为组织 query，覆盖任务执行路径相关 AO/Segment 子集，必带 coverage_manifest（omitted ranges 与理由、watermark），沿用 Q97 结构约束；不做全轨迹重写或固定窗口（Q109-A）。
73. **独立异步索引服务**：与 outbox/aggregator 同模式的服务端索引服务承担 post_run 生成——workspace 级预算与速率上限，优先级 evaluation > 失败轨迹 > 成功轨迹，超限降级 deterministic fallback 或明确无 projection，supersede 旧 projection 退出索引只留审计，workspace 可暂停（Q110-A）。
74. **视图按 session/task run supersede 演化**：后续 commit 的 post_run 构建产生 superseding revision；旧 revision 保留为历史证据（诊断可引用）但 projection 退出检索，避免重叠视图瓜分配额、半成品冒充完整经验（Q111-A）。
75. **分层配额与统一检索信封**：Interaction lane 独立候选预算不占 12；causal-memory lane 内 12 为查询级总帽（默认 Fork/Branch 6、Block/Claim projection 4、Segment/Atom 2，profile 可调总帽不变）；8-4 通道切分只对有状态语义对象生效。接口层统一卡片信封（kind、来源通道、通道内 rank、状态标签、来源指针）与单份 ranker feature spec，存储与 ranker 仍分 corpus（Q112-A + M1）。
76. **投影通道跟随 grounding**：被 validated ForkRevision grounding 的 block/claim projection 可进 verified 通道并带 provenance；未被 grounding 或仅被 provisional/invalidated 引用的保持 provisional（Q113-A）。
77. **投影 ACL 继承与再投影**：projection 继承来源 AO/Segment 安全标签；ACL 变更事件经 outbox 触发再投影/撤下，引用它的 Fork grounding 标 needs_revalidation；redacted 节点仍是下钻路径断点（Q114-A + M2 联动）。
78. **worker 并发层级规则**：评测迭代内统一并发 5；独立诊断 run 沿用 ≤3 sub-diagnosis worker；dossier 增量再诊断预算不变（Q115-A）。
79. **自主监听检索**：非评测任务中 Memory Agent 对频道每条消息跑完整三段式检索，不设前置过滤器、不设 workspace 父级预算上限，由模型自判停止（retrieval profile 停止条件仍是硬约束）；capability = 频道成员 ∩ 来源 session ACL（Q116-B/Q118-B/Q120-B）。
80. **投递节流**：同一 task lineage 对同一 target agent 未决 Hint 上限默认 2、冷却窗口、同 provenance 去重；target agent 可声明偏好（defer-all/按类型过滤）；用户可要求静默；超时只记 exposure（Q119-A）。
81. **L2/L3 不合并，中间路线 M1–M4'**：经双重独立评审（独立子 agent + cursor/grok-4.7）否决合并——fork:anchor 1:1 稳定身份 vs fork↔view M:N、Q99 三层信任分离、可见性矩阵、生命周期频率、检索特征五面承重墙。采纳 M1 接口统一、M2 grounding 内容寻址快照 + needs_revalidation、M3 定位重述（post_run 视图 = AO 台账的派生轨迹索引，系统只有一层长期因果记忆 L3）、M4' 投影引用账隔离（Q121-A；写入 ADR-0010）。
82. **子目标依赖模式查询**：检索查询可为"子目标 + 依赖模式"（匹配 Claim 的 carried_artifact/downstream_effect 签名），命中后仅在同一冻结视图内沿 Claim 有界邻域展开，读时拼装不落对象；不铸造 subtask_id，跨任务命中仍按 task_id 记 cross-task（Q122-A）。
83. **grounding 反向索引 = 干预史**：对已是 influence_grounding 目标的 block|edge|cut 维护倒排索引（outbox 派生、可重建）；READ_VERIFY 可读对应 Fork/Branch 摘要与验证状态、标"干预史"；不改变 Claim 状态、不进 citation/utility。正向 = fork 自带 grounding 字段（权威数据 + M2 快照），反向 = 派生索引，语义刻意不对称（Q123-A）。
84. **跨任务泛化仍在簇**：泛化 = 已验证相似边 + 簇条件 branch_pattern 效用；不搬到影响图节点（防相似性传递走私、block 无跨任务稳定身份）；诊断经反向索引只读联结（Q124-A 重申）。
85. **多根因有界子集对照**：不加节点根因字段、不造 cause_set；修理 = 完整 Branch + cut grounding + 一任务多 Fork；仅过六门槛且 diff 含 ≥2 处可分离改动的高价值分支，在同一 ControlContract 下做 ≤2 个预声明子集配对 replay，记 supporting evidence（subset_sufficient/not_sufficient），可分期先按整支充分性 + partial_match 落地（Q125-A）。
86. **因果检索初排两档**：fork/branch、影响图投影、segment/atom 的初排是纯 BM25，或 BM25 与真实向量的混合。默认纯 BM25。没有真实向量时混合档这一次仍按纯 BM25 返回。不设只有向量的一档，子串匹配退出初排（Q127、Q128-A）。
87. **fact 通道暂停**：混合检索暂时不返回 segment/atom。fork/branch 与影响图投影照常进入结果。AO 台账仍在，诊断仍可分页读 AO。默认配额 6/4/2 留作恢复后的配额；暂停期间不重开「没覆盖 / 最近未诊断」这条覆盖规则（Q129 暂停）。
88. **暂停时空位不回填**：fact 的 2 个位子留空，不转给 fork 或投影。一次结果最多 6 张 fork 加 4 张投影。查询级总帽仍是 12（Q130-A）。
89. **Memory Agent 以卡片 id 展开邻域**：展开工具只给 Memory Agent，参数只有 claim 投影的卡片 id。服务端解析 view 与 claim。模型可不调用。诊断 agent 不使用这个工具。`ov_find` 仍只搜文档（Q131-A）。
90. **诊断历史检索不对齐 claim 签名**：失败路径上的 C1、C2 不要求在历史 view 里找到同文、同序的边（历史 `retrieval-implementation/Q134-B` 否定；与后文已定的 `memory-search-entry/Q134-B` 是不同 decision track）。当时开放的历史命中单位随后由 #92–#97 闭合为模型划定的失败检索子图，以及最多 3 份历史子图与其内部接地 fork。
91. **群聊子图不依赖事先的子任务名单**：群聊里往往只有用户的一个任务，各 agent 的子任务没有事先写下的结构化名单。不能把「跑之前已有的子目标」当作影响图子图的边界（Q138-A 在该场景不成立）。
92. **检索子图由模型在提取时划定**：没有事先名单时，提取影响图的模型把动作划成子图并写入冻结 view。诊断检索是子图对子图的模糊相似，发生在提取之后。不铸造 subtask_id。不用整张 view 当一条查询（Q139-B，Q140 排除整图查询）。
93. **只有失败子图发起诊断检索**：当前 DIV 里只有含坏结果的那个检索子图去查历史子图。旁路子图不自动查询（Q141-B）。
94. **失败子图由结论块规则选定，诊断 agent 发起**：含 conclusion 块的检索子图是失败子图。诊断 agent 只能用它去查历史子图，不能改查旁路子图，也可以不调用（Q142-B）。
95. **诊断子图命中最多 3 份**：每份是一份历史检索子图，加上影响定位落在该子图内的 fork。子图内 block 不超过 12。不足 3 份不回填。旁路子图不返回（Q143-B）。
96. **多份失败 fork 不要求同一次成套召回**：两份普通 fork 分两次检索各命中一份即可。不为它们新造 fork 种类，也不绑成一组（Q145）。
97. **每个失败子图各写一份 fork**：带自己失败结论的检索子图，诊断 agent 各发起一次检索，各写一份普通 fork。之后各次检索分头命中。不合成一份 fork，也不绑在同一次结果里（Q146-A）。
98. **子图内的失败结果即该子图的失败结论**：切流里的「错误率升高」、迁移里的「schema 不匹配」各自成立。通知没有失败结果，不写 fork。任务级结论「发布失败」不单独再发起一次检索（Q147-A）。
99. **失败标记由提取模型写入**：标记和检索子图一起写入。诊断 agent 不改标记，只对带标记的子图发起检索（Q148-A）。
100. **再次使用 fork 的一般情况是另一个任务**：不假定第二次还跑同一个任务。用旧 fork 的七段原文做查询匹配，打不中另一个任务的不同措辞（Q149-B 在该情况下不成立）。
101. **诊断等 commit 后的子图提取再做子图对子图**：子图只在轨迹提交之后提取。诊断等这次提取完成、检索子图划定之后，再用子图检索历史子图。任务进行中不提取子图，也不做诊断的子图检索（Q150-A，Q152）。
102. **子图只由 commit 后的提取产生**：Memory Agent 不持有子图提取工具，也不在进行中提取子图。Q151 的「由子图提取工具接替」被取代（Q152）。
103. **Memory 不触发 diagnosis，也不持有子图提取工具**：diagnosis 仍在 commit 之后触发。进行中提取已取消（Q152）。
104. **诊断子图命中里的 fork 带七段与分支摘要**：历史子图仍在命中里。接地的 fork 带七段快照和分支动作摘要，不带 guidance 全文，不带原始 AO（Q144-B）。
105. **混合检索的 fork 卡片带七段与分支摘要**：进行中的 fork 卡片带七段快照和分支动作摘要，不带 guidance 全文，不带原始 AO。claim 卡片仍是轻量投影。整张 view 不进这次结果（Q133-B）。这覆盖叙述 17 里「交回的卡片不含七段」那一层；guidance 与原文仍不进卡片。
106. **邻域展开只走 influence**：从一张 claim 卡片出发，只沿 `relation_type=influence` 走。`skip` 留在冻结 view 上，展开不踩。某一截只靠 skip 连着时，停在缺口这边（Q132-B）。influence 仍按两端登记、双向走；本题不改方向。跨过覆盖清单省略区间的边必须是 skip，并在两端各带证据。

78. **Revision-level 分级归因（Q126-A）**：每个具体 `skill_revision_id` 的下游消费按 `eligible → offered → selected → invoked → applied → followthrough → objective_outcome` 形成不可变事件链，并以 `invocation_id` 绑定 task/run、context/cluster 与 outcome policy version；offer/exposure/citation 和生成方自报均不计 utility。唯一 applied revision 的真实结果记 observational evidence；满足 ControlContract 的配对相对差异记更强的 counterfactual evidence；多个 revision 同时 applied 且未逐一消融时只记 `confounded_set` 联合证据，不向各 revision 复制完整正效用。
79. **Evidence decay 而非 revision TTL（Q127-B）**：普通 outcome evidence 按 policy-versioned 时间函数衰减并回归中性 prior，skill revision 不因发布年龄自动失效或删除；context/cluster、工具、模型、schema、证据与 ACL 漂移触发重验并可加速旧证据退出当前排序。历史事件永久保留；严重安全/完整性事件不随时间自动洗白。
80. **Active 冷启动走独立探索（Q128-B）**：新 `published_active_skill_revision` 立即 online eligible，但以中性 utility prior 进入独立 seeded-exploration 配额，记录 eligible set、seed、selection propensity 与 revision 曝光/调用上限；达到版本化最小有效 outcome 证据量前不进正常 exploitation。高 uncertainty 只提高探索资格，不直接提高 exploit 排名，也不挤占既有 provisional 3+1 配额。
81. **安全硬门与普通负效用双通道（Q129-A）**：可信的严重安全、权限越界、provenance integrity、撤销或 executable incompatibility 事件单次即可立即 quarantine，使 revision 退出在线检索与执行，恢复须显式重验、新 revision 或授权解除；普通失败、低收益与用户纠正进入负向 utility posterior，达到最小有效样本与置信阈值后降权，并以升降不同阈值的 hysteresis 防震荡。两通道不得压成一个加权总分。

- **GuidedCounterfactualBranch**：群聊 `@memory retrieve` 仅做检索；`@memory diagnose` 才可启动诊断，模糊意图需澄清。协调器复用同一 AIG pipeline；Reader 依据冻结 AIG、证据与分层 Fork precedent 提出 guidance plan，服务端冻结 GuidanceDocument，Memory 仅发布已批准内容并 @ 服务端按角色/能力/ACL/可用性选择的 target agent。自动 dispatch 已接受，但仍必须 fail-closed 通过服务端 ACL、capability、permission、budget、安全和幂等门。
- **任务成败与 remediation**：Reader 提交 TaskOutcomeAssessment；服务端以 OutcomeEvidencePolicy 及任务开始时冻结的 OutcomeContract 裁决 `success | confirmed_failure | uncertain`。confirmed failure 可自动进入 GuidedBranch 与 dispatch；uncertain 的显式 diagnose 仅能生成诊断/建议，不能自动执行。已结束失败任务的真实后续行动必须在 linked remediation run/child session 中发生，绑定 source Fork/Guidance，并以 GuidanceExecutionReport 映射 imagined node 与实际 AO-derived Block；只有对齐行动回流为 production-direct evidence。

本轮的不可逆边界、遗留 ADR 关系与后续实施约束见 [ADR-0043](./docs/adr/0043-aig-native-fork-overlay-and-guided-remediation.md)。这取代既有共识中将 Claim/Cut、独立 L3 Fork、新诊断写入者、Memory 触发限制或 target-agent 手动采纳描述为**新写模型**的部分；历史记录仍仅供审计。不得自动进入产品代码实现。

### Memory disposition 回执（cycle 002，Q190–Q216，2026-10-13，已定案）

**`memory-disposition-receipt/Q190–Q216`：`memory_disposition` 是唯一回执**。被点名的任务 agent 用常驻原生工具 `memory_disposition` 提交 `adopt | reject | defer`。Memory Agent 的工具围栏不包含该工具，且不能成为 Hint 目标。服务端在投递时生成 `hint_id`。频道正文是 Hint 内容，并用 `@` 点名目标；目标可见的结构化字段是 `hint_id` 与 `memory_disposition`。用来投递 Memory Hint 的 Memory Offer 就是这次投递。exposure 只在投递给目标时记录一次。`defer-all`、类型过滤和用户静默不产生投递、exposure 或 disposition。模型提交 `hint_id`、`decision`、`reason` 和可选的 `intended_action_refs`；服务端写入调用者与 `decided_at`。`reason` 留在 disposition 事件上。可选引用按提交内容保存，不证明动作已发生，也不是 followthrough。`adopt` 与 `reject` 一旦写入即终止。`defer` 离开未决名额，并在该 Hint 既有投递 TTL 内允许一次 `adopt` 或 `reject`；再次 `defer` 返回原记录且不刷新 TTL。事件只追加。当前采纳意图是最新一次被接受的决定。投递 TTL 与冷却的默认时长仍未定（OQ-003）。新写入时按调用者当前 ACL 复查 Hint 冻结来源：仍可读的来源各写一条 citation，`adopt` 与 `defer` 记 `considered`，`reject` 记 `rejected`；不可读来源不进入这次 citation。已投递来源不再按当前检索资格、退役或 quarantine 重判。`applied`、followthrough 与正向 utility 的既有规则不变；`adopt` 成功前的动作不算 followthrough。工具说明要求采用前调用，服务端不冻结其他工具。同一 `hint_id` 串行处理。工具不发送频道消息。频道成员资格只在投递时检查。调用顺序为：形式不完整则任何调用者得到「无效参数」；调用者不是现存 Hint 的目标则得到同一种无权失败；重复当前终止决定或再次 `defer` 返回原记录；终止冲突得到「已终止」；超时的新写入得到「已过期」；空 reason 得到「无效参数」且不查来源权限、不消耗替换；来源全部不可读得到「不可处置」并列出来源标识；否则写入新 disposition，结果返回已保存记录和因权限略过的来源标识。失败不写记录。本条不授权产品代码变更。

### 默认 Memory Agent（cycle 003，Q217–Q235，2026-10-13，已定案）

**`default-memory-agent/Q217–Q235`：一个 Workspace 一名 Memory Agent**。本条取代 ADR-0016 与 CONSENSUS #15 中「每个新建群各自 provision 一名具有独立 identity 的 Memory Agent」。不按 task 或 thread 临时创建仍然有效。每条消息的权限仍是该频道成员资格 ∩ 来源 session ACL，成员身份不隐式提权。

一个 Workspace 只有一名 Memory Agent。第一个能够创建它的新建群创建它：公开，显示名 Memory，handle 为 `memory`，所有者是该群创建者。Computer 绑到该创建者在此 Workspace 最早的一台；没有则先不绑，待该创建者有 Computer 后再绑最早的一台。群创建不因此失败。记录仍在时，之后的新建群只加入这一名，使用其当前 handle；创建者的成员选择不能排除它。它在所属群中不静音。同一 session 接收这些群的消息。新建 Workspace 的 `#general` 是第一个新建群。本决定之前已存在的群不会被自动加入。把其他公开 Agent 编入 `#general` 时，也不把这名 Memory Agent 加进它尚未加入或已经离开的群。私聊不是群。

`memory` 被活着的 Agent 或成员用户名占用，且 Workspace 还没有这名 Memory Agent 时，该新建群照常创建，但不加入 Memory Agent，也不因此切换 profile。占用者保留该名字。已软删除的同名 Agent 不占用名字。名字空出后，下一个新建群完成创建，并尝试把 desired profile 设为 `openviking`。此前被跳过的群不自动补成员。

创建时把 desired profile 设为 `openviking`。已经是 `openviking` 时不产生新的激活游标。游标之后关闭的公共频道分段按既有 profile 语义入库，包括没有 Memory Agent 的频道。游标之前已关闭的分段不入库。原型开关拒绝切换时，群与 Memory Agent 仍创建，profile 保持 `off`，失败记入既有 profile 失败记录，记忆工具保持关闭。开关随后允许时重试该切换，不必等待下一个新群，也不因该 Agent 当前不在任何群中而取消。从一个群移除成员不改变 profile。

可以从某个群移除。该群此后没有 Memory Agent，直到有人用该群既有的添加成员操作把当前这一名加回。移除不删除 Agent 记录。本决定之前的群、因名字占用而跳过的群、以及软删除后未自动换上新成员的群，都可以用同一种添加操作加入当前这一名。本决定不自动修改它们。

改名后仍是同一名。之后的新建群加入改名后的这一名。另建的同名任务 Agent 不是第二名 Memory Agent。不能改为私有，修改被拒绝。停止只暂停运行；记录仍在，之后的新建群仍加入这一名。软删除可以成功，其公共频道成员资格标为已离开，历史消息保留。下一个新建群在名字空闲时创建一名新的公开 `@memory`，使用新的 identity 与 session，不继承被删历史。Computer 与 profile 尝试按这次新的创建计算。原先有过旧成员的群不自动加入这名新 Agent。

本条不重开 Memory Hint 回执、检索、followthrough、outcome utility，也不设定 Hint 投递 TTL 与冷却的默认时长（OQ-003）。不授权产品代码变更。
