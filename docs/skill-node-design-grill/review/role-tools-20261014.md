## Current role surfaces

| Role | Model-callable tools | Function and output |
|---|---|---|
| Builder | `T_log`: `get_overview`, `read_full_segment`, `read_step`, `read_step_range`, `list_agents`, `get_question`, `search`, `list_block_kinds`, `get_story`, `get_graph`. `T_build`: `add_block`, `add_inheritance_note`, `add_skip_attribution`, `modify_block`, `delete_block`, `delete_inheritance_note`, `delete_skip_attribution`, `mark_defect_recorded`, `submit`. | Starts from an empty draft over a frozen AO snapshot, reads evidence and writes four paper node types plus inherited/effect edges. Hard invariants are checked on calls; `submit` seals the draft. Call/time/repeat budgets can produce a provisional fallback marker. |
| Critic | `get_graph`, `get_story`, `get_overview`, `get_question`, `read_step`, `read_step_range`, `search`; no build verbs. | Server runs structural `Phi(G)`; model audits semantic fidelity and granularity, returning high/low `PaperViolation`s. No task-outcome authority. |
| Refiner | All `T_build` except `submit`, plus `get_graph`, `read_step`, `read_step_range`. Every edit names a `violation_id`. | Repairs draft within violation scope for at most three critique/refine rounds. High-severity residue produces fallback; low-severity residue may freeze with `known_violations`. |
| Reader | `get_graph`, `get_story`, `get_overview`, `get_question`, `read_step`, `read_step_range`, `search`; no build verbs. Separate `T_fork` design: `search_precedents`, `submit_fork_proposal`, `submit_guidance_plan`, `expand_experience_links`, phase and outcome gated. | Navigates frozen graph, reports responsible agent, decisive AO refs, reason, critical block, unresolved areas. Freezes a ReaderReport; fork/guidance actions are separately gated by confirmed failure. |

The role separation, immutable handoff intent, frozen snapshot, programmatic structural check, 3-round cap, and server-side fork gates are sound boundaries. The tool inventory is broadly sufficient for the happy path, but the current contracts leave serious false-trust and repair gaps.

## Findings, in priority order

1. **Critical — Critic failure can be treated as clean.** `GemmaCriticProvider.__call__` returns `{violations: []}` after `_validated` exhausts retries, with `fallback=empty_violations` only in a separate failure list. `run_critic_refiner` interprets no violations as immediate freeze. Offline probe with a transport exception: `cycle_status=frozen`, `known_violations=[]`, failure recorded. Require an explicit audit status; unavailable or invalid audit must not yield a trusted frozen graph.
2. **Critical — Raw AO tools can expose hidden prompts.** `list_agents` omits `system_prompt`, but `_step_text`, `read_step`, and `search` use the AO action unchanged. Synthetic AO with `action.system_prompt` gave `list_agents_contains_prompt=false`, `read_step_contains_prompt=true`, `search_matches_prompt=1`. The same `T_log` verbs are available across roles. If production AO rows carry that field, the claimed prompt-hiding boundary is bypassed. Redact restricted fields before every read/search projection, then check that snapshot hashes still bind the unredacted source internally.
3. **High — Reader can freeze unsupported attribution.** `parse_reader_report` checks the critical block exists, the agent name matches, and `decisive_ao_refs` equal that block's full `step_refs`. It does not check which AO rows Reader read or whether `reason` follows the edge effect. Offline probe: zero read calls, invented reason, empty unresolved list, `trust=frozen`. The strict full-span equality also prevents citing the one decisive row inside a multi-row block. A report should carry checked evidence refs and an explicit verification status; server policy must govern trusted downstream use.
4. **High — Reader budget exhaustion still freezes a trusted empty report.** `run_reader` creates an empty `ReaderReport` on budget exhaustion, then calls `read_verify` and `freeze_report`. Offline probe: `critical_block_id=""`, `trust=frozen`, `authorize_outcome_write` succeeds. Keep an incomplete report for audit, but deny outcome/fork authority until verified.
5. **High — Semantic edge defects and node-split repairs have no expressible path.** Critic output permits only a block `object_id`, with `semantic|granularity` kind; an edge ID is rejected. `RefinerSession._check_scope` permits only `modify_block` for those kinds. Offline probes reject both a false-edge deletion and adding a block to split a coarse block. Introduce typed edge violations, evidence refs, and bounded repair operations; keep server-side scope enforcement.
6. **High — Model and toolloop outcomes are not a production default.** `trajectory_index_hook.py` still documents fallback for no provider and `native_single_pass_aig` for injected extraction; the toolloop/Reader/T_fork path is exercised in benchmark code. ADR-0045's evaluation direct injection is deliberate, but an end-to-end accepted design is not yet an active production ingest path. Do not report the four roles as deployed production behavior.
7. **Medium — Reader phase/report composition is brittle.** On an empty Critic audit, `run_critic_refiner` freezes a revision without calling `AigConstructionRun.submit_draft`. Passing that run directly to `run_reader` raises `no_draft`; the benchmark catches this and manually backfills a draft before Reader. The orchestration API should establish its own handoff invariant.
8. **Medium — Refiner history is not durable at each edit.** `AigToolSurface.apply_refine` changes in-memory state while the submitted builder log remains sealed. The orchestrator appends the round only after `run_refiner_round` returns. A crash between an edit and that append loses the committed repair, while replay rebuilds the pre-refine draft. Persist each accepted refiner operation atomically with its violation ID and prev hash, or make the round transactional.

The one-call `read_full_segment` and untruncated `read_step` tools are useful for AO fidelity, but also allow large raw disclosures with no per-role output or token envelope visible in the surface. That is a design and security-boundary review item, especially because prior archive rules specify summary-first escalation. Scope the tool output to authorized evidence and budget before promoting this surface beyond controlled offline evaluation.
