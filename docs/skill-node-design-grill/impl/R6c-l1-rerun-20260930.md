## 归因（按提交）

`git log e8a8babf4..HEAD -- openviking/session/retrieval_facade.py` 只有 6 个提交，其中改到初排/通道的只有分支第一个：**`988148ad8`（R0/R1，`feat(session): rank causal retrieval with BM25 and pause the fact lane`）**。它同时做两件事：

1. **fact 通道暂停**（`FACT_LANE_PAUSED = True`，`retrieval_facade.py:114`）→ 这就是 HEAD P=0%、空并集 100% 的原因（#87/#88：暂停时空位不回填）。跑分器构造门面时不传 `fact_lane_paused`，取到的就是常量默认值。
2. **子串匹配退出初排、改 BM25**（同一个提交引入 `openviking/session/bm25.py` 与 `RANK_MODE_BM25`）→ 这就是「掰回开启后 15.2% 低于 base 17.3%」的原因（#86 定案：子串匹配是过滤器不是排序器）。

**证据链**：base 没有 `FACT_LANE_PAUSED` 这个属性（`/tmp/ov-base` 里 import 报 `AttributeError`），所以 base 与 HEAD-flipped 的差 = 初排从子串换成 BM25 的差；HEAD 与 HEAD-flipped 的差 = 暂停本身。两条都在同一提交的同一次定案内，无法再细分到更细粒度（也不需要）。

**注意口径**：base 的 17.3% 是「子串命中的卡片按插入序取前 12」下的命中率（评测方案自己写过「子串匹配是过滤器不是排序器（`_score` 恒 1、插入序输出）」），HEAD-flipped 的 15.2% 是「BM25 取前 12」下的命中率。**两者不是同一把尺**，2.1pp 的下降应读作「换排序器后的量级变化」，不是质量回退的证明；但可以确定的是：**fact 通道即使开着，离参考上限 T 的 61.8% 还差约 46pp**——这正是评测方案说「rerank 注入点该收回来的那部分」的量化。

## 这一轮 R6c 到底完成了什么、还差什么

**完成**：L1 的**回归核对**——分支 15 个提交在离线零 LLM 指标上没有引入新回归；同时把「P 臂为什么是 0」查到底并归因到已定设计。

**没完成**：本波工作真正要量的**因果通道**（fork/branch ＋ 投影）在 L1 上**仍然没有数字**。原因是跑分器本身：它构造门面时 `projection=InfluenceProjectionAdapter(ProjectionRegistry(work / "unused.jsonl"))`（**没有注册任何视图**）、profile 是 `{fork: 0, projection: 0, segment_atom: 12}`（fork/投影座位都是 0），T 臂也不走门面。也就是说：**它的 P 臂只量了 fact 通道**，而我们这一支改的是 fork/branch 与 block/claim 投影。要给因果通道出第一个离线数字，需要：

1. 在跑分器里把「确定性 fallback InfluenceView ＋ 注册进 `ProjectionRegistry`」这条链补上（评测方案的 arm B：+ Block/Claim 投影，零 LLM）；
2. profile 改成带投影座位（例如 `{projection: 4, segment_atom: 8}` 或投影/事实分列两臂），并对齐「暂停时空位不回填」的口径；
3. 复用同一个 hit@k 判分（gold evidence 回查），产出可与 T 上限对照的数字。

**这三步都要改 `benchmark/causal_memory/l1_locomo_hitk.py`（既有基准文件）**——按用户定的「不动 `benchmark/`，除非签名需要，动前报」，**停在这里等裁定**。另：L2（配对 replay）与 L3（collab 四件套）依赖**已被用户暂停的 live 栈与模型额度**（`eval/NEXT.md` 的后台进程、grok-4.6/DeepSeek 端点），本波不碰；#125 的提取输出契约也应该等 arm B/C 有数字后再定。
