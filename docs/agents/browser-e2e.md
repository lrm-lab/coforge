# Browser end-to-end tests

Read and follow this guidance when writing, running, or reviewing the browser e2es in
`apps/web/test/*.e2e.ts`. Moved out of `testing.md` to keep it under the size gate; the rules
are unchanged.

- `apps/web/test/*.e2e.ts` are opt-in: `bun test` does not discover `.e2e.ts`, and per-commit CI never runs them; the files listed in `scripts/e2e/web-e2e-ci.txt` run daily in `.github/workflows/web-e2e.yml` ([Web browser e2e](../release/web-e2e.md)). Never run one with `ego-browser`: it drives the signed-in desktop browser of whoever owns the machine. They need a local Web service, `agent-browser`, and a local database. Each file's doc comment states its own prerequisites and what it writes under `.amp/e2e/`.
- Run one by name: `mise run test:e2e:web` lists them, `mise run test:e2e:web <file>` runs one (the `.e2e.ts` suffix is optional). Use `scripts/e2e/run-web-e2e.sh` directly when you want the listing without mise.
- **A change that restructures the DOM the e2es select against (a page's sections, headings, row lists) sweeps the tracked set before it merges: `mise run test:e2e:web:all`.** It runs every file in `scripts/e2e/web-e2e-ci.txt` one after another and reports a pass/fail line each; a file with unmet prerequisites fails loudly with the missing value named. Files not yet on the list (no three clean runs yet) are run by name. Selecting a page belongs to the shared helpers (`test/helpers/`), not to copies inside e2e files - `apps/web/test/web-e2e-selectors.test.ts` guards that rule.
- **Pass the file as a path, never as a bare name.** `bun test e2e-x.e2e.ts` treats the argument as a _filter_ and runs zero tests, printing only a hint; `bun test ./test/e2e-x.e2e.ts` loads the file. The two spellings differ by one `./`, and `scripts/ci/test-invocations.test.ts` guards the invocations that scripts, `mise.toml` and workflows name.
- The shared runner defaults `COFORGE_E2E_WEB_URL` to `http://127.0.0.1:8788`, the dev server's port (the same default `run-mobile-overflow.sh` uses). The standard managed stack publishes Web on **8789** instead, so a file run against that one needs `COFORGE_E2E_WEB_URL=http://127.0.0.1:8789`.
- **A dev database whose user has no `displayName` must be re-seeded, or every browser e2e fails with no diagnostic.** The sign-in flow needs the user's `displayName`, which `apps/web/scripts/seed-dev-data.ts` supplies and an older row lacks; without it the dev session cannot complete sign-in and the app redirects to `/en/welcome`. Every browser e2e then fails with `Wait timed out after 25000ms`, and neither the Web's stdout nor Centrifugo's log says why, because the workspace layout never mounts and so no realtime connection is even attempted. Re-run `apps/web/scripts/seed-dev-data.ts` against the same database; diagnose by instrumenting the test's proxy to print request paths (the `/en/welcome` request is the tell), not by reading logs.
- **A realtime e2e needs a third variable, and a Centrifugo that knows where its Web is.** `apps/web/test/e2e-read-cursor-elsewhere.e2e.ts` throws `COFORGE_E2E_CENTRIFUGO_URL is required` without the client-facing Centrifugo origin, which the shared runner does not set. Separately, `infra/centrifugo/config.yaml` points Centrifugo's client-token JWKS at the _managed_ stack's Web (`:8789`), so a private stack whose Web is on 8788 must also override `CENTRIFUGO_CLIENT_TOKEN_JWKS_PUBLIC_ENDPOINT` to `:8788/api/jwks` - the log's `JWKS manager created endpoint=` line is the check, and the Web's `/api/jwks` should answer 200. Overriding it is necessary but not sufficient: the Web must also bind **`HOST=0.0.0.0`**, because the Centrifugo _container_ fetches that JWKS over the docker bridge and a loopback-bound Web answers `connection refused` (`host.docker.internal` resolves to `172.17.0.1`). The failure is silent from the app's side: the browser's `/connection/*` reaches the proxy, Centrifugo refuses the handshake with `invalid token`, and nothing appears in the Web's output. Check with `docker exec <centrifugo> wget -qO- http://host.docker.internal:8788/api/jwks`. With all four in place, `e2e-read-cursor-elsewhere.e2e.ts` passes (measured: 1 test, 5.73s).
- **Two host facts decide whether any of this works, and both fail as if the product were broken.** Chrome needs `AGENT_BROWSER_ARGS=--no-sandbox` where unprivileged user namespaces are unavailable (`CHROME_FLAGS` and `BROWSER_ARGS` are _not_ read by `agent-browser`); without it every file dies in seconds with `No usable sandbox!` from `zygote_host_impl_linux.cc`. And the Web must be _served_ with `NODE_ENV=development` while it is _built_ with `NODE_ENV=production` - the order `scripts/e2e/managed-web.sh` uses - because production serving leaves the browser on the marketing page, unauthenticated, so every step waits out `Wait timed out after 25000ms` and a run looks like five product failures. Measured on 2026-09-30: the same file and head gave 5 timeout failures in 132s with production serving, and 5 passes in 18s with development serving.
- A private stack needs no `infra/secrets`: `scripts/e2e/prepare-environment.ts` generates the worker JWK, the agent credential key and the Web-push keys under `.amp/e2e/`, and `apps/web/scripts/seed-dev-data.ts` + `apps/web/scripts/start-server.ts` (both under `apps/web/scripts/`, not the repo root) build the rest from environment variables.
- A file that needs more than the shared environment (Centrifugo, the worker key material, a provider key, a viewport) has its own runner and mise task; run it through that one. The shared runner sets `DATABASE_URL`, `REDIS_URL` and `COFORGE_E2E_WEB_URL` only.
- A new browser e2e needs no wiring to become reachable: the runner lists the directory, so it is runnable the moment the file exists. Its prerequisite checks must throw with the missing value named, never skip silently, so that an unrun test is visibly unrun rather than green.
