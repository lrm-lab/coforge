# Agents' app access

An app installed in a Workspace ([app registry](apps.md)) is usable by that Workspace's Agents.
`apps/web/src/server/app-agent-access/` owns who may change an Agent's access and when an Agent
may use an app (`decideAgentAccess`). Migration `20261020200000_app_agent_access`.

- The first time an Agent asks to use an installed app it gets a grant automatically (source
  `automatic`). After a person revokes it, the row stays revoked, so the Agent's next use creates
  a pending request instead of a new grant; only a person's approval (or grant) gives it back.
- A grant's scopes are the app's fixed scopes (`openid`, `profile`, `identity`) and any others the
  app allows (`email`) that were asked for. A use asking for a scope the active grant lacks also
  waits for approval, of the grant's scopes and the new one. A use is granted only the grant's
  scopes the app still allows, so narrowing an app's `allowedScopes` applies to the next token.
- Workspace owners and admins, and the Agent's creator while a member, grant, revoke, approve and
  deny (`canManageAgentAppAccess`, the `manageAgentAppAccess` capability). Every member who can see
  the Agent reads its access. A person's grant also approves the Agent's pending request for that
  app when it covers the request's scopes.
- An Agent uses an app through `coforge app token`, which applies this rule and mints its
  five-minute token ([Agent tokens](../authorization-server/README.md#agent-tokens)). A request it
  opens gets at most one approval card (`action_cards.kind` `app:grant_agent`, its `payload` naming
  the request), posted with the request row locked and only while it is pending: committing the card approves the request, cancelling it denies the request, and a
  request decided anywhere else (the Agent's Apps tab, a person's grant) settles its card in the
  same transaction: `executed` when approved, `cancelled` when denied.
- An installation can limit Agents to a selection ([Agent access scope](apps.md#agent-access-scope)).
  Under `selected`, an Agent outside it that has no grant is not granted automatically: its use opens
  a pending request, as after a revoke. A person's grant works for any Agent. The Agent is told of
  an app (the launch prompt's Apps list, `coforge app list`) only when it is in scope or has an
  active grant. Switching to `all`, or adding an Agent to the selection, restores the automatic grant
  for the Agents then in scope that have no row, and approves their pending requests in the same
  transaction (grant source `automatic`; the request's and the card's deciding person is the owner or admin who
  changed the scope, and the approval card is settled `executed` and refreshed in open browsers, best effort); an
  Agent with a revoked row still needs a person.

`app_agent_grants` — one row per app and Agent:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | UUID | UUIDv7 primary key, generated by the Prisma client. |
| `appId` | UUID | The app, cascade delete. Unique with `agentId`. |
| `agentId` | UUID | The Agent, cascade delete. |
| `workspaceId` | UUID | The Agent's Workspace, cascade delete. |
| `scopes` | TEXT[] | A subset of the app's `allowedScopes`, always with the fixed scopes. |
| `source` | TEXT | How it was last given: `person`, `automatic` or `approval` (`app_agent_grants_source_check`). |
| `grantedByUserId` | UUID | The person who gave it; null for an automatic grant. Set null when the User is deleted. |
| `createdAt` | TIMESTAMP(3) | |
| `updatedAt` | TIMESTAMP(3) | When it was last given or revoked; an active grant shows it as when it was given. |
| `revokedAt` | TIMESTAMP(3) | Set by a revoke, cleared when it is given again. |
| `revokedByUserId` | UUID | Set null when the User is deleted. |

`app_agent_access_requests` — an Agent's request waiting for a person:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | UUID | UUIDv7 primary key, generated by the Prisma client. |
| `appId`, `agentId`, `workspaceId` | UUID | Cascade delete. |
| `scopes` | TEXT[] | The scopes an approval grants (those the app still allows). |
| `status` | TEXT | `pending`, `approved` or `denied` (`app_agent_access_requests_status_check`); at most one `pending` per app and Agent (`app_agent_access_requests_one_pending`, a partial unique index). |
| `createdAt` | TIMESTAMP(3) | |
| `decidedAt` | TIMESTAMP(3) | When it was approved or denied. |
| `decidedByUserId` | UUID | Set null when the User is deleted. |

A denied request leaves the grant revoked; the Agent's next use opens a new pending request.
